## 4. 根本原因への批判的評価
**失敗の構造（優先順）**
1. 出力の「量」を品質と誤認：本物のBlenderでも一つの画面に細いシアン水帯・灰色梁・箱状建物しか見えない。ARTは未達。
2. **造形アルゴリズムの形態的固定化**：flat quads／長梁／単純ロックパッチ／規則的反復。材料や名前を変えても平面の輪郭・光・機能的な立体感は変わらない。R27は最も強い否定証拠。
3. 元カメラを真に先行しない制作：新施設が見えない、見えても近すぎて画面を塞ぐ。R26サイト可視ゲートは必要だが**十分条件ではない**。
4. 単体施設の積み増し：取水→水位差→導水→制御塔12→タービン42→岸壁の「なぜそこにある」が初見で読めない。建造物は地形の荷重経路／水理に一体化させる。
5. 高速走行時の時系列を軽視：180〜190m/s級では0.1sに約18〜19m移動。静止3枚・5枚の綺麗さは認知・公平性・面白さを保証しない。
6. CI/資料循環：CI成功/失敗修正や文書整理が実際の美術改善以上に増えた。R25 git status不明、R27 same-tick noiseで停止。失敗原因がARTかQAかは区別するが、**ART不採用候補の緑化だけにCIを費やさない**。
7. HUMANからの乖離：本人の「つまらない」「JSONが分かりにくい」という過去評価を背景制作の完了感で覆わない。ARTの節目で本物プレイへ接続。

**批判の自己反証と修正**
- 「抽象的な設計をずっと続ければ良い」→却下。計画だけではARTは改善しない。安価な可視/画面試験を短く終え、**一つの実DCC候補まで進む**。見込みがない場合は早期停止して質を優先。
- 「次は巨大で細密な3Dを置く」→R26/27が否定。尺度と実カメラの主従を先に合わせ、近景に空を残す。
- 「完全な地形生成関数さえ作ればARTになる」→却下。実RAWと陰影・材料・機能を人間の視点でレビュー。単なる関数名/ポリゴン細分化は禁止。
- 「数値閾値だけでART合否を自動化」→却下。遮蔽の診断は必要だが恣意的な画素閾値で美術を合格にしない。
- 「人間評価まで実装を止める」→却下。ART制作とTECH検証は研究として進め、HUMANは適切な候補が現れるまでHOLD。最初の実試走は簡単にする。
- 「保護されているCamera/物理を動かせばすぐ見栄えがよくなる」→現在は権限外。現行制約内で画面を作る。制約下で目標達成不能という**本物の実証**が得られたら勝手に変更せず別承認を要求する。
- 「すべてを一つの長時間CIで強行」→失敗とコストを増やす。軽量ゲート→単独実造形→少数真RAW→良い候補だけ深い評価の**条件付き一括工程**に修正する。「一括」は無条件フルCIという意味ではない。
