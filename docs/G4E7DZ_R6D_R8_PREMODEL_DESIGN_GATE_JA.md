# R8設計ゲート — 部屋・入口・移動・視線が完成してから造形する

R7は6空洞を本当に掘り、32斜路を本当に作り、元B48/B51とのサンプル干渉ゼロを確認しても、体験は未達。特に17秒の中庭可視0／8本の4フライト全経路接続0。**R8の第一目標は建物を1棟追加することではなく、この失敗の原因を解くこと**。

## A. 元世界実測による「通過できる都市断面」

- R1真正11〜17秒の元240Hz走行カメラとプレイヤーの軌跡、元B48実三角形、B51全28体×721時点の標本を読み込む。
- 一般の未来都市街路を目指す場合も、元ゲーム道路の幅やP96物理を都合よく変更しない。
- 連続する都市内部・目の前の生活面・車輪の接地・危険な見通しを同時に考える。架線・塔・巨大門の背景追加で代用しない。

## B. 実在する歩行経路グラフ

- 起点をR5Aで候補化した既存CX面の真正座標に置き、出口を一つ以上決める。
- 入口→公共床→乗換→居住への分岐→出口について、3D接続点・床の面積・本来の歩行方向・踊り場・階間をひとまとまりの**検査可能なネットワーク**として設計する。
- 近接距離1m以内は暫定診断のみ。**近接のみで歩行可能、構造荷重成立、車両安全とは宣言しない**。
- R7が許容1mでも8連続経路すべてFAILだった失敗を防ぐため、造形の前にグラフ整合・接続端点の一致を判定する。

## C. 空間が実カメラから本当に見えること

- 11〜17秒の前・中・遠距離に公共・居住・交通を置き、レイ遮蔽によって見える実内部の建築体積を検査する。
- 床に穴が開いているのに実画像では「棚と鉄骨」にしか見えない状態を拒否。中庭の中心点だけが画角内にある条件は不採用。
- 早い11〜13秒の存在感、14〜15秒の街区への接近、16〜17秒の内部通過と離脱のつながりを人の目でも審査する。ただし11〜11.5秒の非接地を無条件ゲームFAILとしない。

## D. 研究作業・採否判定・効率

- 初回は**建築1系統、最小の真正3D**に限定し、接続と視界検査に失敗したら全域100メッシュ超の装飾生成は行わない。
- アート採択には元R1と同じ正規7視点の真正Blender実画像が必要。人間・本番WebGL・操作・アクションは別ゲート。
- 原物保護：CX18/B48 7/B51 28/元カメラ5/gap52、CX Git blob `af076d67492a677d2235e4730aef8cdf4808e106`、main、Gold、本番、原ゲーム物理・操作、新コライダー0。
- 長期運用ではR7Cの**FAIL FAST**を新モデルや新トポロジーのデータ形式に合わせて再利用する。形だけのCI回数を増やさず、一度の実作業で設計→検証→証拠→判定を完結させ、追加変更をまとめて一つのGit更新にする。
