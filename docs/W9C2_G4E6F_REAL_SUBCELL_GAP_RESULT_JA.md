# W9-C2 G4E-6F — 衝突面を細分化して「本物の短いギャップ」を比較

2026-10-20。ブランチ `p101-velocity-overdrive-native-trial`、Draft PR #46。**人間操作、一般公開、正式採用、mergeはすべてHOLD**。

## ここまでの経緯

- G4E-6Eでは第I道路の実物理欠損セル位置を6つ比較。第I道路の**制御格子31×5・物理res=3＝90縦セル**の実原本を守った最良E0-C048は、6.96mの実ギャップ→自然離陸→元の道路へ再接地→7/7完走。速度維持率94.6%、57.421s、Goldの53.275sとの差+4.146s。
- ギャップの位置だけを動かした改善は前版より25ミリ秒と小さく、目標「Gold比+3s以内」に届かない。第I道路の空中時間の追加だけではなく、第II〜VII道路へ遅延が連鎖している。
- そこでG4E-6Fでは**別の衝突格子分解能**を持つ完全独立候補を比較。路面の見た目や原本31×5制御点、7道路ID・routeSegments・spawn・28障害物は変えないが、**第I道路の衝突三角形の位置と数は元のGoldと異なる**。よってGoldやG4E-6Eの合格を継承できず、毎案実際の240Hz start00で検証した。

- `tests/p101-w9c2-g4e6f-subcell.test.mjs`：原本Goldの制御点・他6道路・route・routeSegments・全28障害物・spawnsの不変と、**実際に欠損したB48三角形数**を確認。無許可のサイズ・siteを拒否。
- `scripts/p101-w9c2-g4e6f-subcell-native.mjs`：既存の`g4e6NativeRun`をそのまま使用し、入力だけ個々の独立3D地形に差し替える。物理・重力・速度制限・移動機械・操舵方針・ジャンプ力は変更なし。実離陸、18tick継続の本当の再接地、7道路すべての順序、完走、着地速度を個別に測定。
- `.github/workflows/p101-w9c2-g4e6f-subcell-native.yml` はCIにNode構文検査、unitテスト、正規start00全コース240Hz比較、未承認判定、エビデンス保存を追加。初回のスクリプト末尾誤りとCLI出力漏れを修正して成功した。**このCIのSUCCESSはデータ計測と監査がPASSした意味であり、すべての候補が完走した意味ではない**。

### 判定の注意点

- 3.48m案は空中へ飛び出し、元の道路へ再接地しながら、後続の**移動障害物と物理接触が収束せず**に失敗。加速を伴う速度維持率100%以上を根拠に「より良いコース」とは認定できない。
- 6.96mの高分解能案は65秒内にfinishせず、計測時点で明示的な物理failがない。**TIME LIMIT / INCOMPLETE**とし、衝突で失敗したとは記述しない。
- 4.64m案のF9-147-2は実7/7、着地時速度104.5%を満たすが57.992s（+4.717s）。早い着地速度は7.28km全体のタイム短縮を保証しない。
- 今回の**厳格な高速品質基準（Gold比+3秒以内を含む）に合格した候補は0件**。最速かつ93%以上の速度維持と7/7を両立した研究候補は依然としてG4E-6EのE0-C048（57.421s・94.6%）である。
- 「実ギャップ・自然離陸・道路への着地」という局所物理は複数の独立設計で確認できた。しかし**人間の回避操作、自然な視認性、カメラ、FPS、コース全体の遊びの面白さ**は確認していない。Slope2 DNA 40%への正式加算距離は**0m**。

## 今後の設計方針

セルの数mm/数m単位調整だけで数秒の損失を消そうとする研究は、現時点では効果が小さい。**元の第I道路の下り方・自然飛行の弾道・後続のカーブ・移動機械接触**というゲームプレイ全体で評価すべき。

次はG4E-7で、ローカルの2候補試走（C0-55-1、B0-65-1）を通じて人間の主観的な速度感・ギャップの発見しやすさ・回避の難易度を確認する。必要なら候補に実視覚ガイドやコース構造の改善を検討する。絵だけの狭路や見えない床による「ギャップ加算」は禁止。
