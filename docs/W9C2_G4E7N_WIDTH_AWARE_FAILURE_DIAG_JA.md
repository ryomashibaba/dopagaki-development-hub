# DOPAGAKI W9-C2 G4E-7N — 実B48細道の事故原因と操舵診断（2026-10-22 JST）

**これは新たな自動操舵機能の採用ではない。** G4E-7Mで作った本物のB48 13〜16m幅のTHREAD/ PRECIPICE・Gold・GLIDE・28実機械・240Hz物理・ボール相対カメラ・速度／スコアに変更なし。研究用の独立したヘッドレスP96操舵だけの診断である。正式Slope DNAは0m、PR #46 Draft、非公開研究、ユーザーWindows人間4走はHOLD。

## 根本原因の測定
既存P96のearly-softプロファイルは`laneMeters=25`で障害物の反対側へ25mずれることを要求していた。G4E-7M THREADではCROWNの実B48道路幅は約13–16m。この25mは路面の半幅6–8mを遥かに超える。

- THREAD・従来P96：**10.12083秒、CROWN_REVERSAL道路の実`edge`非走行面へ静止致死接触**。法線方向の衝突速度は **−12.870m/s**。直前CROWN u=.1431の実道路幅**12.807m**で位置横v=.9246、u=.16508ではv=**1.0107**（実路肩を逸脱）。接近する対象は`p95-hazard-01`で要求オフセット25m。移動障害物接触は失敗まで0。
- THREAD・`route-only`：最初のCROWNエッジを回避したが、21.725秒の第III道路`SCISSOR_RISE`で`p95-hazard-04`の移動sliderに接触して失敗。
- THREAD・`dodge-3m`：同じくCROWNエッジの早期事故を回避、しかし21.74167秒、後半の移動sliderへの接触で失敗。
- THREAD・**`width-aware-narrow` 研究用**：真B48幅をそのフレームで読み、最初の2道路に限り25m回避補正を幅の22%程度へ縮め、3道路以降は元の回避へ戻す（Game/WebGLは未変更）。**51.89583秒で7/7完走、移動障害物接触0**。
- PRECIPICE・元P96：従来通り52.67917秒で7/7完走。
- GLIDE・元P96：従来通り51.81667秒で7/7完走。

## 解釈
広い道路向けのP96回避目標と実B48細道との**コントローラ不整合**がTHREADの早期路肩衝突の主要な原因。道路自体を広げたり、中央安全帯を追加したり、赤障害物を除去したりせずにヘッドレス制御条件の変更だけで完走したことがその反証となる。

**注意**：この検証で使ったwidth-aware操舵は完全なスクリプト制御で、人間の入力、反応時間、視界、FPS、難易度、公平さ、ゲーム全体としての面白さを証明していない。G4E-7Nはゲーム本体の操舵・加速度や道路形状を一切書き換えていない。既存の広幅向けP96モードとのベンチマークは不適切な点があるため、今後は本物の人間による操作を独立して確認する。
